# Internal pilot runbook

This is a local, single-tenant product rehearsal. It does not submit a claim to a real vendor or confirm a real credit. Use the supplied synthetic contract and incident data; do not upload customer records until an approved retention policy, encrypted backups, and trusted system integrations are in place.

**Signup change (15 October):** a new signup is a pending access request and receives no session. An existing administrator must use Accounts → Enable before that person can sign in. Do not enable unknown requests: approved accounts share this pilot's workspace. Existing accounts remain usable. See [security controls](SECURITY.md).

1. Open `http://localhost:3000/login`. Choose **Sign up first** if you want your own operator account; enter your name, username, and a password of at least 14 characters. Sign-up is enabled only by setting `SELF_SIGNUP_ENABLED=true` in the private local `backend/.env`; it is disabled by default for packaged or hosted deployments. Local admin and reviewer credentials are in `work/pilot-accounts.txt` on this machine, outside the release ZIP. Use **pilot-reviewer** to decide cases and **pilot-admin** to run simulated vendor actions. Sign out before changing roles. Passwords are stored as salted scrypt hashes in SQLite; browser sessions expire after 12 hours and can be revoked by signing out.
2. As the operator, open `/intake`. Upload the supplied synthetic cooling-SLA PDF at `backend/app/data/contracts/ThermaCore_Master_Service_Agreement_2026.pdf`. Check every extracted term, then save. The original PDF is stored in the local SQLite database and linked to the saved contract by its SHA-256 file checksum. Alternatively, enter terms manually; those contracts have no archived PDF.
3. Enter a unique incident ID such as `pilot_manual_001`, ticket and vendor-acknowledgement times, telemetry, and maintenance status. For the supplied source files, use the UTC values shown in `backend/app/data/incident_sources` (convert them to your local time in the form). The case is saved in review. Operator-entered records are labelled unverified.
4. On the case review page, still as the operator, click **Attach pilot sample files** for `pilot_manual_001`, or attach the supplied `ticket-synthetic.json`, `telemetry-synthetic.csv`, and `maintenance-synthetic.json` under their matching source types. Each file is stored with a checksum. The bundled structured exports are compared with the entered incident; mismatches are shown and block approval if selected. This does not authenticate file origin. If the incident fields are wrong, open **Correct incident information**, click **Fill bundled pilot values**, then **Save correction and reassess**. The correction keeps the previous values in the audit.
5. As the reviewer, compare the contract PDF, entered incident, and each source file. Inspect model citations, contradictions, and proposed amount. Select each checked file and explain the comparison. The uploader cannot verify their own file. Approval is blocked until ticket, telemetry, and maintenance sources have been checked.
6. To rehearse missing information, record **Request information** as the reviewer, sign in as the operator, open **Correct incident information**, update the affected fields, explain the change, and reassess. The case keeps its previous incident values and remains in review. A fresh reviewer approval is required.
7. As the reviewer, record **Approve for simulation** if the evidence and policy gate support the claim. Sign in as the admin for simulated submission, dispute, acceptance, and credit reconciliation.

The internal pilot exit criteria are: signed-in role enforced, source files retrievable after restart, no manual case approval without a distinct reviewer source check, stale review/correction rejected, conflicting evidence held, prior correction values retained, no duplicate simulated credit booking, and no credential in the frontend or release ZIP. The current automated tests cover role enforcement, identity-backed audit, sources, PDF, correction, and backup/restore checks. The historic live evaluation used synthetic demo cases, not uploaded customer contracts.
